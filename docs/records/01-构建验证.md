## 二、过程中踩到的三个坑（都已处理或有解法）

### 坑 1：wrapper 非要重新下载 Gradle 发行包（已绕过）

**现象**：`./gradlew` 报 `Could not install Gradle distribution from 'https://services.gradle.org/distributions/gradle-9.5.0-bin.zip'. Reason: SocketTimeoutException: Read timed out`

**排查结论**：本机**已经装好了** Gradle 9.5.0（`~/.gradle/wrapper/dists/gradle-9.5.0-bin/bvnork1r7n8i6kp5cnkibsc9q/`，406 个库文件、无空文件、`.ok` 标记齐全）。而且：
- 用 wrapper 自己的算法（URL 的 MD5 转 36 进制）算出来的目录名 `bvnork1r7n8i6kp5cnkibsc9q` 与实际目录名**完全一致**；
- 两个项目的 `gradle-wrapper.jar` sha256 一致；
- wrapper 的检查规则是"缓存目录里恰好一个子目录且含 `lib`"，本机状态符合。

**即按 Gradle 自己的规则，它就不该下载。** 具体触发原因未定位到（需要完整报错前几行才能确定），但影响已消除。

**附加原因**：即便要下载也会失败——`services.gradle.org` 现在只是跳板，**真正的文件在 GitHub Releases 上，该域名在这个网络下 25 秒下 0 字节**。

**当前绕法**（不经过 wrapper，零下载）：
```
GD=~/.gradle/wrapper/dists/gradle-9.5.0-bin/bvnork1r7n8i6kp5cnkibsc9q/gradle-9.5.0/bin/gradle
"$GD" -p ~/Work/Android/TLoggerDemo :TLogger:build
```

**待办**：确认是否要把 wrapper 的下载地址换成国内镜像（一次改动，以后所有 Gradle 版本都不再走 GitHub）。不换也不影响开发，只是每次新建项目可能会再碰到。

### 坑 2：`androidLibrary` 块在 AGP 9.3 上已弃用（待处理）

**现象**：
```
w: TLogger/build.gradle.kts:13:5: 'KotlinMultiplatformExtension.androidLibrary(...)' is deprecated.
   The 'androidLibrary' block is deprecated. Please use 'android' instead.
```

**含义**：AGP 9 起，跨平台库的安卓配置块从 `androidLibrary { }` 改名成 `android { }`。目前只是警告、不影响构建。

**处理**：**等构建变绿之后再改**（一次只动一件事，避免把"新写法有没有问题"和"依赖能不能拉到"两件事混在一起查）。

**记录价值**：这正是体检报告里说的"新写法踩坑的人少"——我们的支持矩阵里必须写明"AGP 9.3 用 `android { }`"。

### 坑 3：`repo.maven.apache.org` TLS 握手被中断（已修）

**现象**：
```
Could not get resource 'https://repo.maven.apache.org/maven2/.../kotlin-test-2.2.10.pom'
> Remote host terminated the handshake
```

**实测各地可达性**（本次测量）：

| 仓库 | 结果 |
|---|---|
| `repo.maven.apache.org`（Gradle 的 `mavenCentral()` 指向它） | 本机 200 / 0.8 秒；**用户环境握手被中断** |
| `maven.aliyun.com/repository/public` | 200 / **0.045 秒** |
| `mirrors.cloud.tencent.com` | 200 / **0.056 秒** |
| `dl.google.com` | 通（AGP 已成功拉取） |

**已做的修复**：`settings.gradle.kts` 里加入阿里云镜像并置于 `mavenCentral()` 之前，官方仓库保留兜底。

> 说明：**没有全线不通**。AGP、跨平台插件都拉下来了，只有走 `repo.maven.apache.org` 的那部分被卡住。

## 三、顺带确认到的两件事

1. **配置文件缓存（configuration cache）报了一个序列化错误**，位置在 `:TLogger:compileAndroidHostTest`。但它是由"依赖解析失败"引发的（Gradle 试图序列化一个没解析成功的文件集合）。**依赖修好之后需要复验是否还存在**——如果还在，说明是跨平台插件与 Gradle 9.5 的配置文件缓存不兼容，届时要么关掉缓存、要么去掉宿主测试。
2. **宿主测试（host test）已生效**：报错里出现了 `:TLogger:compileAndroidHostTest`，说明 `withHostTestBuilder {}` 那个"不需要真机的单元测试"通道是通的。
